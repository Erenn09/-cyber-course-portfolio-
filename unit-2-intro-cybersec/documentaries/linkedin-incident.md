# LinkedIn Incident

The LinkedIn breach took place in 2012, when attackers stole an amount of user data. I was surprised that the full amount of stolen data only became years later in 2016.

Than one hundred million LinkedIn accounts were affected. The leaked information could later be used to attack websites because many people reused their passwords.

The main CIA principle affected was confidentiality because private user information and password hashes were stolen. The loss of confidentiality also damaged trust because users expected LinkedIn to protect their information.

A hash algorithm changes a password into a fixed string that should not be easily turned back into the password. LinkedIn used SHA-1, which was weak because the same passwords produced the same hashes. A salt adds data to each password before hashing making stolen hashes harder to crack.

The breach happened in 2012 but the stolen data became years later. This shows that stolen data can stay useful for a time so the risk starts when the data is stolen not when the public first hears about it.

LinkedIn could have used a stronger password hashing method with a salt for every password. This would have made the stolen password data harder for attackers to use.

Companies should protect user passwords properly because a breach can affect users on other services too. Users should also use passwords so a leaked password from one website cannot be used to access their other accounts.

Using passwords on important accounts. I would use a password manager. Make sure my important accounts have unique passwords and MFA enabled.
