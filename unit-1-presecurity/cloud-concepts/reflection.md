### 1. Cloud in your own words
-  I would explain it as using computer resources that belong to another company instead of buying and taking care of your own servers. You can rent things like storage, computing power and software from a provider and use them through the internet. This is different from buying a computer because you do not own the physical equipment and the provider takes care of it.

### 2. Traditional → Cloud → Containers
- The main idea behind all these stages is to make IT resources easier and more efficient to use. Traditional IT needed physical servers, while virtualization made it possible to run several virtual computers on one physical server. Cloud computing made these resources available when needed, and containers made applications easier to move and run in different environments.

### 3. Deployment vs Service models
- A deployment model explains where the IT infrastructure is located and who operates it, for example on-premises, private, public, hybrid or multi-cloud. A service model explains how much of the technology is managed by the provider, such as IaaS, PaaS or SaaS. One example of public cloud + SaaS is Microsoft 365, because Microsoft provides the service through its cloud and users can use applications like Teams and Outlook.

### 4. The Shared Responsibility Model 
- The Shared Responsibility Model means that both the cloud provider and the customer have security responsibilities. The provider protects the underlying infrastructure, but the customer is still responsible for things like accounts, passwords, permissions and how their data is configured. For example, an Amazon S3 storage bucket can accidentally be made public because of an incorrect customer configuration, which can expose data even though the cloud provider itself was not hacked.

### 5. Why organisations still hesitate
- One reason is laws and regulations about where data can be stored, especially in the EU because of GDPR. Another reason is that cloud costs can be difficult to predict because many services use pay-as-you-go pricing.

### 6. Cloud in an entry-level tech role
- A help desk worker could help a user who cannot log in to their Microsoft 365 account. They might also receive an alert about a suspicious login to a cloud account and need to check the account or send the problem to the security team. This shows that cloud services can be part of normal IT support work even if the person's job is not called cloud engineer.

### 7. Your personal takeaway
- After this lesson, I have a different understanding of the word “cloud.” I used to think it was mostly something found in the sky, but now I understand that cloud services are still tied to real servers, networks, and data centers.
